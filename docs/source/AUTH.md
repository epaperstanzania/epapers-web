# Phase 2 auth contract
Access tokens are returned in JSON and kept in SPA memory. Send Authorization: Bearer on private routes. Refresh tokens use HttpOnly, Secure, SameSite=Lax cookies scoped to /api/v1/auth. Development needs HTTPS for cookies. Both hosts must share a registrable domain; cross-site hosting needs a revised cookie policy.
Every POST/PATCH/DELETE requires Origin equal to APP_ORIGIN and X-EPapers-Client: web. Send credentials: include for refresh/login/logout. Preflight permits only the configured origin.
Registration, OTP resend, and forgot-password use generic responses. Register and forgot-password remain public with rate limits and CSRF checks. Profile username changes reserve historical usernames permanently and apply the configurable 30-day cooldown. Registration always creates a contributor and rejects role fields. Operators assign lecturer/admin roles. New/reset passwords require at least six characters with a letter and number; uppercase and symbols are optional.
Run the worker separately with environment loaded: node --env-file=.env --conditions=react-server --import tsx worker/index.ts. Email delivery uses an outbox and retries; it is at-least-once (a crash after sending can duplicate an email). SMTP daily budget defaults conservatively to 450 and can be configured. Confirm the sending limit of your Google account before production.
Admin login requires a six-digit code sent to the account email, with ten-minute expiry and five attempts. The first password request returns a challenge without creating a session. POST /auth/admin/verify-login consumes it and creates the session. Authenticator enrollment is no longer required. The outbox remains encrypted using DATA_ENCRYPTION_KEY. See [the complete email login flow](ADMIN-EMAIL-LOGIN.md).
Only cf-connecting-ip is trusted for IP limits. Restrict direct VPS access and have Cloudflare overwrite that header; otherwise clients can spoof it. Database counters keep limits consistent across processes.
Endpoints: POST /auth/register, /auth/verify-otp, /auth/resend-otp, /auth/login, /auth/admin/login, /auth/refresh, /auth/logout, /auth/forgot-password, /auth/reset-password, /auth/change-password; GET /auth/me, /auth/sessions, /auth/username-availability?username=; DELETE /auth/sessions/{id}; PATCH /users/me.

POST /auth/change-password requires a bearer token and `{ "currentPassword": "...", "password": "..." }`. It checks the current password and new password policy, revokes all sessions, consumes pending authentication challenges and clears the refresh cookie. Sign in again after success. Contributor and administrator Settings include this form with password confirmation and Show/Hide controls.

POST /auth/reauth requires an authenticated admin and password, and sends an email code. POST /auth/reauth/verify verifies the challenge and code and returns a five-minute reauthToken with a separate JWT audience. Sensitive admin handlers use withAuth({roles:['admin'],requireReauth:true}) and X-EPapers-Reauth. Reauth tokens are bound to the current live session and cannot serve as access tokens.

The SPA must coordinate refresh requests so only one runs at a time; simultaneous reuse intentionally revokes the session family. Login and refresh return explicit session DTOs internally as well as explicit JSON projections.
